AI-chat Architecture

A local-first chat client with two interchangeable backends — one running in the browser on WebGPU, one on any OpenAI-compatible server on your network. No server of our own, no build-time secret.

Five layers, one direction of travel

src/
  App.jsx  main.jsx  index.css

  state/
    conversation.js      pure reducer
    useConversation.js   owns useReducer

  features/
    chat/       components/ hooks/
    models/     components/ hooks/
    sessions/   components/ hooks/
    settings/   hooks/

  services/
    providers.js         facade
    openai.js            HTTP adapter
    llm.js               WebGPU adapter
    sessionStore.js      IndexedDB

The dependency rule

features/* may import state/ and services/ — never another features/*.

Checkable by resolving every import and comparing top-level folders. Currently holds with zero exceptions. Cross-folder imports use the @/ alias, so nothing counts ../ hops.

What actually downloads, and when

The split rests on one detail: providers.js duplicates the model id constant rather than importing it from llm.js. Listing the available models must not pull in the module that drags the runtime behind it.

Chunk Size Fetched
index.js 67 kB initial load
llm.js 148 kB first WebGPU use
ONNX WASM 5.8 MB first WebGPU use

Model weights add roughly 390 MB on top, downloaded once and cached by the browser when the user clicks Load Model.

Schema reflects the codebase as restructured: shared conversation state lifted to state/, settings folded into features/, IndexedDB access moved under services/, and a @/ path alias in place. The prose version with full detail lives in docs/architecture.md.
